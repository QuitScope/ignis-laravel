# Import aus dem Altsystem

`php artisan ignis:import-legacy` liest die Datenbank eines laufenden Ignis/intraRP (das Altsystem) und legt die Daten in der neuen Instanz an oder aktualisiert sie. Das Altsystem wird nie verändert. Übernommen werden Rollen, Konten, Einladungscodes, Audit-Log, die Anmelde-Einstellungen, Personal (Stammdaten, Akten, Fachdienste, Profilbilder, Akten-Log), die Verknüpfung Konto zu Akte, die Dokumente (Vorlagen, Editor-Dokumente, Altdokumente mit ihren PDFs), die Fahrzeuge (Wachen-POIs, Fahrzeuge, Mängel mit Verlauf, Beladelisten, TZ-Vorlagen, entschiedene Register-Einträge), die Benachrichtigungen, die Schnellzugriffe und ausgeblendete Ankündigungen, die Systemkonfiguration (`intra_config`, mit Logo) und die Modul-Schalter (`intra_plugins`) sowie die Daten der Fachmodule (Fahrtenbuch, Wissensdatenbank, Anträge, Kalender, MANV-Board, FireTab, eNOTF, Mail, Vernetzung; Einzelheiten unten).

## Voraussetzungen

- Die neue Instanz ist installiert (`/install` bzw. `ignis:install`), sonst bricht der Befehl ab.
- Das Altsystem ist auf dem **letzten Stand** (alle Phinx-Migrationen gelaufen). Fehlen Tabellen, nennt der Befehl sie und bricht ab (`Legacy tables missing: ...`). Ist `phinxlog` älter als die zuletzt analysierte Migration (`20261016100001`), erscheint eine Warnung im Bericht. Sobald Dokumente importiert werden (also auch bei einem Lauf ohne `--only`), ist der Stand Pflicht: `phinxlog` muss `20261016100001` enthalten und die Vor-Editor-Tabelle `intra_dokument_templates` darf nicht mehr existieren, sonst bricht der Befehl vor dem Schreiben ab (siehe "Dokumente").
- Ein **Datenbankbenutzer mit nur `SELECT`-Recht** auf der Altdatenbank. Das ist die eigentliche Garantie, dass nichts verändert wird. Die Klasse `LegacyReader` verweigert zwar jede Anweisung, die kein Lesen ist, aber das ist nur ein zusätzliches Sicherheitsnetz (ein Muster auf dem SQL-Text), kein Ersatz.
- Die Altdatenbank muss vom Container bzw. Server der neuen Instanz erreichbar sein (Firewall, `bind-address`, Benutzer mit passender Host-Angabe).
- Backup der **neuen** Datenbank vor dem ersten echten Lauf (siehe INSTALL.md, Datensicherung).

## Umgebungsvariablen

| Variable | Bedeutung |
|---|---|
| `LEGACY_DB_HOST` | Host der Altdatenbank. Ohne Wert ist die Verbindung nicht konfiguriert und der Befehl bricht ab. |
| `LEGACY_DB_PORT` | Port (Standard `3306`). |
| `LEGACY_DB_DATABASE` | Name der Altdatenbank (Standard `legacy`). |
| `LEGACY_DB_USERNAME` | Benutzer (Standard `root`; stattdessen den SELECT-Benutzer setzen). |
| `LEGACY_DB_PASSWORD` | Passwort. |
| `IGNIS_IMPORT_LEGACY_TIMEZONE` | Zeitzone, in der das Altsystem Datum und Uhrzeit gespeichert hat (Standard `Europe/Berlin`, die PHP-Zeitzone des Altsystems). |
| `IGNIS_IMPORT_LEGACY_DB_TIMEZONE` | Zeitzone, in der der **Datenbankserver** des Altsystems lief, als er `DATETIME`-Spalten mit `NOW()` füllte (Fahrzeug-Entitäten, Benachrichtigungen, ausgeblendete Ankündigungen), z. B. `Europe/Berlin` (Zonenname, keine feste Verschiebung). Leer (Standard): die Zone, in der der Altserver jetzt läuft, mit einer Warnung im Bericht. Beim Import aus einem wiederhergestellten Dump **setzen**. Siehe "Zeitzone". |
| `IGNIS_IMPORT_LEGACY_BASE_PATH` | `BASE_PATH` des Altsystems, wenn es unter einem Unterpfad lief (z. B. `/intra/`). Wird aus den Links der Benachrichtigungen und den Zielen der Schnellzugriffe entfernt. Leer (Standard) oder `/`: nichts wird entfernt; der Import rät den Wert nie. Siehe "Benachrichtigungen, Schnellzugriffe, Ankündigungen". |

`LEGACY_TEST_DB_*` gehört den Tests und wird vom Import nie gelesen (siehe `docs/dev/tests.md`).

**Docker:** Die Werte in die `.env` neben `docker-compose.yml` schreiben (Vorlage: `docker/.env.example`) und `docker compose up -d` ausführen. Das erstellt den Container `app` neu und baut den Konfigurations-Cache mit den neuen Werten. `docker compose exec -e ...` wirkt nicht, weil die Konfiguration beim Start gecacht wird. Danach:

```
docker compose exec app php artisan ignis:import-legacy --dry-run
```

Nach der Umstellung das Passwort wieder aus der `.env` entfernen und `docker compose up -d` erneut ausführen.

**Ohne Docker:** Einträge in `.env` setzen und danach `php artisan optimize` (oder `php artisan config:clear`) erneut ausführen, weil die Konfiguration gecacht ist (INSTALL.md schreibt `php artisan optimize` vor).

### Zeitzone

Das Altsystem speichert Zeitpunkte als Ortszeit. Der Import rechnet sie aus `IGNIS_IMPORT_LEGACY_TIMEZONE` in die Zeitzone der neuen Anwendung (`app.timezone`) um. Spalten vom Typ `TIMESTAMP` zeigt MariaDB allerdings in der `time_zone` der **Sitzung** an. Läuft der Altserver in UTC (`SELECT @@global.time_zone, NOW();` prüfen), obwohl PHP in `Europe/Berlin` lief, die Variable auf `UTC` setzen, sonst verschieben sich diese Zeitpunkte um die Zeitverschiebung. Im Zweifel einen bekannten Eintrag (z. B. einen Audit-Eintrag mit bekanntem Zeitpunkt) nach dem Trockenlauf vergleichen. Ein ungültiger Zeitzonenname bricht den Lauf vor dem Schreiben ab.

**Zwei Uhren (Fahrzeuge).** Das Altsystem schrieb manche Zeitpunkte mit PHP (`date()`, Zone `IGNIS_IMPORT_LEGACY_TIMEZONE`) und andere mit der Uhr der Datenbank. Die Fahrzeug-Importer behandeln sie **je Spalte**:

- **`TIMESTAMP`-Spalten** (`created_at`/`updated_at` von Fahrzeugen, POIs, Mängeln, Mangel-Verlauf, Beladelisten, TZ-Vorlagen, `created_at` der Register-Einträge) sind Zeitpunkte: MariaDB speichert sie in UTC. Der Import liest sie mit `UNIX_TIMESTAMP(spalte)` je Wert, also unabhängig von der Zone des Servers und der Sitzung, richtig über Sommer- und Winterzeit hinweg und ohne Zeitzonentabellen.
- **`DATETIME`-Spalten, die mit `NOW()` gefüllt wurden** (`resolved_at` der Mängel, `processed_at` des Registers, `status_updated_at` der Fahrzeuge mit Quelle `incident`, die fireTab schrieb) sind Wanduhrzeit des Datenbankservers beim Schreiben. Sie werden in `IGNIS_IMPORT_LEGACY_DB_TIMEZONE` gelesen. Ohne Wert nimmt der Import die Zone, in der der Altserver jetzt läuft (`@@session.time_zone`, bei `SYSTEM` `@@system_time_zone`; ein Zonenname rechnet Sommerzeit richtig, eine Abkürzung oder feste Verschiebung nicht), und schreibt eine **Warnung** mit `@@global.time_zone`, `@@system_time_zone` und der verwendeten Zone. Das stimmt nur, wenn der Server beim Schreiben in derselben Zone lief.
- **`status_updated_at`** mit Quelle `manual`, `no_dispatch` oder leer schrieb PHP: Zone `IGNIS_IMPORT_LEGACY_TIMEZONE`.

Der Bericht nennt die verwendeten Uhren (Hinweis bei `vehicle`). Audit-Zeitstempel (`intra_audit_log.timestamp`) sind jetzt ebenfalls Zeitpunkte (Test mit `SET GLOBAL time_zone`). Die übrigen Entitäten (Personal, Dokumente, Vorlagen, Einladungscodes, Nachschlagelisten) rechnen weiter nur mit `IGNIS_IMPORT_LEGACY_TIMEZONE`.

**Import aus einem Dump.** Wird die Altdatenbank per `mariadb-dump` gesichert und auf einem anderen Server wiederhergestellt, bleiben `TIMESTAMP`-Werte Zeitpunkte (`mariadb-dump` schreibt sie standardmäßig mit `--tz-utc` und stellt sie so wieder her). `DATETIME`-Werte werden dagegen wörtlich übernommen: sie bleiben die Wanduhrzeit des **ursprünglichen** Servers. Deshalb beim Import aus einem Dump `IGNIS_IMPORT_LEGACY_DB_TIMEZONE` auf die Zone des ursprünglichen Servers setzen (dort `SELECT @@global.time_zone, @@system_time_zone;`), nicht die des Wiederherstellungsservers.

## Ablauf

1. **Trockenlauf:**

   ```
   php artisan ignis:import-legacy --dry-run
   ```

   Der gesamte Lauf findet in einer Transaktion statt, die am Ende zurückgerollt wird (Einstellungen und Rechte-Zwischenspeicher werden neu geladen). Es bleibt nichts zurück, aber der Bericht ist der echte.

2. **Bericht lesen.** Die Tabelle zeigt je Entität `read` (gelesen), `written` (geschrieben), `skipped` (übersprungen) und `failed` (fehlgeschlagen). Darunter folgen `Notes` (Hinweise, z. B. übernommene vorhandene Rolle), `Skipped` (jede übersprungene Zeile mit Grund und alter ID), `Warnings` (Daten, die geändert oder ersetzt wurden, z. B. leerer Benutzername oder unbekannte Rechte) und `Failures`. Der Befehl endet mit Exit-Code 1, wenn es Failures gibt. Auf Warnings und Skips prüfen, ob sie erwartbar sind; Failures vor dem echten Lauf beheben.

3. **Echter Lauf** ohne `--dry-run`. Am Ende steht im Audit-Log (global) "Altdaten-Import ausgeführt" mit der Zusammenfassung.

Optionen:

- `--only=role,user` (Komma-getrennt oder wiederholt): nur diese Entitäten **und was sie brauchen**. Entitäten: `role`, `user` (braucht `role`), `registration_code` (braucht `user`), `audit` (braucht `user`), `auth_settings`, `rank`, `fire_qualification`, `ems_qualification`, `specialty`, `personnel_title`, `personnel` (braucht die fünf davor), `personnel_log` (braucht `personnel`), `account_link` (braucht `user`, `registration_code`, `personnel`), `document_template` (braucht `user`), `document` (braucht `personnel`, `user`, `document_template`), `legacy_document` (braucht `personnel`, `user`), `poi`, `vehicle` (braucht `poi`), `vehicle_defect` (braucht `vehicle`, `user`), `vehicle_defect_event` (braucht `vehicle_defect`, `user`), `loadout`, `tactical_symbol_template` (braucht `user`), `vehicle_registry` (braucht `user`), `vehicle_audit_context` (braucht `audit`, `vehicle`, `vehicle_defect`), `logbook` (braucht `vehicle`, `user`), `form` (braucht `user`, `personnel`), `kb` (braucht `user`), `calendar` (braucht `user`, `personnel`, `role`, `form`), `manv` (braucht `user`, `personnel`, `account_link`, `vehicle`, `poi`), `mail` (braucht `user`, `personnel`, `role`, `rank`, `ems_qualification`, `fire_qualification`, `specialty`, `account_link`), `notification` (braucht `user`), `dashboard`, `announcement_dismissal` (braucht `user`), `system_settings`, `module_switch`. Ein unbekannter Name bricht ab. Scheitert eine Entität, werden die davon abhängigen übersprungen. Die Modul-Importer laufen nach `vehicle`, `user` und `personnel` und vor `notification` und `dashboard` (deren Links zeigen auf ihre Datensätze): `logbook`, `form`, `calendar`, `manv`, `mail`, `kb` (`kb` nach `calendar` und `manv`, damit Links der Wissensdatenbank auf Termine und MANV-Lagen in einem Lauf aufgelöst werden; mit `--only=kb` allein bleiben sie `/calendar`, bis `calendar` gelaufen ist und `kb` erneut läuft).
- `--uploads=PFAD`: Wurzelordner der Altinstallation (der Ordner, in dem `storage/` liegt). Nur damit werden Profilbilder (`storage/profile-pictures`, siehe "Personal"), Dokument-PDFs (`storage/documents`, `storage/private/editor-documents`, siehe "Dokumente") und das Logo (`storage/branding`, siehe "Systemeinstellungen und Module") kopiert, außerdem die Bilder der Wissensdatenbank (`storage/kb-images`) und die Mail-Anhänge (`storage/private/mail-attachments`). Ein nicht vorhandener Ordner oder einer ohne jeden dieser sechs Unterordner bricht ab. Bei Docker den Ordner in den Container einbinden und den Pfad im Container angeben.
- `--import-api-key`: übernimmt den alten `API_KEY` (verschlüsselt gespeichert). Ohne den Schalter bleibt der Schlüssel der neuen Instanz (Hinweis im Bericht); Clients wie `ef_bridge` brauchen dann den neuen Schlüssel (`ignis:api-key`).
- `--overwrite-settings`: Altwerte ersetzen Einstellungen, die in der neuen Instanz schon gespeichert sind (sonst gilt "der Erste gewinnt", siehe "Wiederholen"). Gilt für `auth_settings`, `system_settings` und `module_switch`.
- `--format=json`: der Bericht als JSON (`dry_run`, `entities`, `warnings`, `notes`, `skips`, `failures`) statt Tabelle, für Skripte.

### Personal

- **Stammdaten** (Dienstgrade, Qualifikationen, Fachdienste, Titel): Eine vorhandene, noch nicht zugeordnete Zeile gleichen Namens (bei Fachdiensten zuerst gleicher Nummer, dann gleichen Namens) (ohne Beachtung der Groß-/Kleinschreibung), z. B. ein Standardeintrag des Installers, wird übernommen und mit den Altwerten überschrieben (Hinweis im Bericht). Doppelte Namen im Altsystem bleiben zwei Zeilen. Zeilen, die nur die neue Instanz hat, bleiben (eine Warnung je Tabelle).
- **Akten:** Die Dienstnummer wird getrimmt; doppelte Dienstnummern (ohne Groß-/Kleinschreibung): die erste Akte gewinnt, die übrigen stehen unter "Skipped". Eine noch nicht zugeordnete Akte gleicher Dienstnummer in der neuen Instanz wird übernommen. Fehlt der Dienstgrad (nicht importiert), schlägt die Zeile fehl; fehlt eine Qualifikation, wird die Zeile "Keine" gesetzt (Warnung); fehlt der Titel, bleibt er leer (Warnung). `discordtag` wird nur übernommen, wenn es eine Discord-ID ist (17 bis 20 Ziffern), sonst leer (Warnung mit Anzahl). `fachdienste` ist im Altsystem eine JSON-Liste der Fachdienst-Nummern (`["211","413"]`); unbekannte Nummern werden gezählt und ausgelassen. Geburts- und Einstellungsdatum sind Kalendertage und werden nicht umgerechnet; ein ungültiges Datum lässt die Zeile fehlschlagen. `createdate` wird wie alle Zeitpunkte umgerechnet. Akten werden ohne Ereignisse geschrieben (keine automatische Verknüpfung über die Discord-ID während des Imports).
- **Profilbilder:** Aus `pfp` zählt nur der Dateiname hinter `storage/profile-pictures/`, und nur bei einem reinen Pfad (`/…/storage/profile-pictures/<name>`); Werte mit Schema oder Host (`https://…`, `//host/…`) werden ohne Bild übernommen (Warnung); das Standardbild (`assets/img/empty_user.png`) bedeutet "kein Bild". Nur mit `--uploads` wird die Datei aus `<PFAD>/storage/profile-pictures/` kopiert: erlaubt sind nur Namen aus Buchstaben, Ziffern, `.`, `_`, `-` ohne `..`; der aufgelöste Pfad (auch über Symlinks) muss im Ordner liegen; Typ (PNG, JPEG, WebP), Größe (2 MB) und Pixel werden wie beim Hochladen geprüft. Die Kopie bekommt einen **neuen** Zufallsnamen (`.jpeg` wird `.jpg`), das Altsystem bleibt unverändert. Ungültige oder fehlende Dateien: Akte ohne Bild, Warnung mit Grund. Ein erneuter Lauf kopiert ein unverändertes Bild nicht noch einmal. Ohne `--uploads` wird nichts kopiert, vorhandene Bilder bleiben, der Bericht nennt "N Profilbilder nicht kopiert". Beim Trockenlauf wird geprüft, aber nichts kopiert.
- **Verknüpfung Konto zu Akte:** `users.personnel_id` über `legacy_id_map`; der Kontoname folgt dem Aktennamen. Eine Akte gehört höchstens einem Konto: das Konto mit der kleinsten alten ID gewinnt, weitere werden übersprungen (Warnung). Eine Verknüpfung, die in der neuen Instanz schon besteht, wird nicht verschoben. Konten ohne Akte bleiben unberührt. Verknüpfungen werden nur gesetzt, nie entfernt: wird im Altsystem eine Verknüpfung gelöst, bleibt sie nach einem erneuten Lauf in der neuen Instanz bestehen (dort von Hand lösen). Einladungscodes bekommen ihre Akte (`registration_codes.personnel_id`).

### Dokumente

Nur der Editor-Stand des Altsystems (ab 2026-09-14) wird gelesen. Zu Beginn wird geprüft: `phinxlog` enthält `20261016100001` und `intra_dokument_templates` (Vorlagen vor dem Editor) existiert nicht mehr. Sonst bricht der Befehl mit `Documents: ...` ab, bevor etwas geschrieben wird.

- **Organisation:** Die Altwerte `SERVER_NAME`, `RP_ORGTYPE`, `SERVER_CITY`, `RP_STREET`, `RP_ZIP` (`intra_config`) übernimmt `system_settings` (Einstellungen `organisation.*`, siehe "Systemeinstellungen und Module").
- **Vorlagen** (`document_template`): Spalten 1:1. Eine Systemvorlage gleichen Namens (ohne Beachtung der Groß-/Kleinschreibung), die der Installer angelegt hat, wird übernommen und mit den Altwerten überschrieben (Hinweis); doppelte Altnamen bleiben zwei Zeilen. Der Inhalt muss die Prüfung wie beim Speichern einer Vorlage bestehen, sonst schlägt die Zeile fehl (`failed`, der Lauf geht weiter). `created_by` über `legacy_id_map`; fehlt das Konto, bleibt es leer (Warnung).
- **Editor-Dokumente** (`document`): Die Kennung (`docid`, 7 Ziffern) bleibt; ist sie in der neuen Instanz schon an ein anderes Dokument vergeben, schlägt die Zeile fehl. Akte, Vorlage, `created_by` und `issued_by` über `legacy_id_map`. Ein Dokument einer nicht übernommenen Akte wird übersprungen (eine Warnung mit Anzahl); fehlen Vorlage oder Konto, bleibt die Spalte leer (Warnung). Status `entwurf` wird Entwurf, `ausgestellt` ausgestellt, ein anderer Status schlägt fehl. Inhalt und `frozen_values` werden wie beim Speichern geprüft; was die Prüfung ablehnt, schlägt fehl (gezählt, kein Abbruch). Inhalt, den die Prüfung annimmt, den der Editor aber nicht öffnen würde (oben nicht nur Abschnitte, leere Abschnitte oder Listen), wird übernommen und als Warnung gemeldet. PDFs nur bei ausgestellten Dokumenten und nur mit `--uploads`: zuerst `storage/private/editor-documents/{docid}.pdf`, sonst (ältere Ablage) `storage/documents/{docid}.pdf`, Ziel `editor/{docid}.pdf` auf der Disk `documents`. Ausgestellte Dokumente ohne PDF stehen als Warnung im Bericht.
- **Altdokumente** (`legacy_document`): **jede** Zeile von `intra_mitarbeiter_dokumente`, in Blöcken zu 1000, über die alte ID wiederholbar. Nichts wird umgewandelt: `inhalt`, `suspendtime`, die Rang-Spalten, `template_id` (bei alten Zeilen falsch, maßgeblich ist `type`) und `custom_data` (als Text, auch wenn es kein gültiges JSON ist; Warnung) stehen in `legacy_payload`. Nulldaten (`0000-00-00`) werden leer, der Rohwert steht in `legacy_payload` (Warnung). Fehlt die Akte (nicht übernommen), wird das Dokument ohne Akte übernommen (Warnung mit den `profileid`). Der Aussteller wird über `aussteller_user_id` und `legacy_id_map` zugeordnet; sonst bleibt nur die Discord-ID (`ausstellerid`, Warnung, z. B. wenn sich zwei Konten eine Discord-ID teilten). Eine Kennung, die in der neuen Instanz schon ein anderes Altdokument hat, schlägt fehl. PDF nur mit `--uploads`: `storage/documents/{pdf_path oder docid.pdf}` wird nach `legacy/{docid}.pdf` kopiert. Der Name ist die Kennung, damit die öffentlichen Links `/storage/documents/XXXX-XXXX-XXXX.pdf` weiter funktionieren (7-Ziffern-Namen bleiben wie im Altsystem gesperrt). Kennungen in anderer Form bekommen kein PDF (Warnung).
- **Kopieren der PDFs:** nur Namen der beiden Kennungsformen (`1234567.pdf`, `ABCD-EFGH-JKLM.pdf`); der aufgelöste Pfad (auch über Symlinks) muss im Ordner liegen; höchstens 20 MB; die Datei muss mit `%PDF-` beginnen. Fehlende oder ungültige Dateien: Zeile ohne PDF, Warnung mit Grund und Kennungen. Eine unveränderte Datei wird beim nächsten Lauf nicht noch einmal kopiert (Hinweis "N PDF(s) copied, M unchanged"). PDF-Dateien in den Altordnern, zu denen es keine Zeile gibt (z. B. von gelöschten Akten), werden gezählt und nicht übernommen. Ohne `--uploads` wird nichts kopiert, vorhandene Kopien bleiben (Hinweis "N ... nicht kopiert"). Fehlt unter `--uploads` der Quellordner einer Art (`storage/documents` für Altdokumente; für Editor-Dokumente der Ordner, in dem das PDF laut Altsystem liegt), gilt das für diese Art genauso: vorhandene Kopien und Links bleiben, eine Warnung "folder ... missing below --uploads". Nur eine einzelne fehlende Datei in einem vorhandenen Ordner nimmt einer Zeile das PDF (das Altsystem ist die Wahrheit). Bei Editor-Dokumenten zählt `pdf_path` des Altsystems, wenn es einer der beiden Orte ist, die das Altsystem selbst ausliefert; ein anderer Wert bedeutet "kein PDF". Eine 7-stellige Altdokument-Kennung, die zugleich ein Editor-Dokument ist, bekommt kein PDF (die Datei gehört dem Editor-Dokument; Warnung). Beim Trockenlauf wird geprüft, aber nichts kopiert (Hinweis "N PDF(s) would be copied").

### Fahrzeuge

Wiederkehrende Abweichungen erscheinen als **eine** Warnung je Art mit Anzahl und den ersten 20 alten IDs (`… (legacy ids: 1, 2, ...)`), nicht als Zeile je Datensatz. Es gilt immer `read` = `written` + `skipped` + `failed`.

- **POIs** (`poi`): die Kernspalten (`name`, `strasse` → `street`, `hnr` → `house_number`, `ort` → `city`, `ortsteil` → `district`, `typ` → `type`, `active` → `is_active`) und seit 9b die Kennung `legacy_identifier` (eNOTF-Ziele; ein Nachlauf ergänzt sie bei schon übernommenen POIs).
- **Fahrzeuge** (`vehicle`): `active` → `is_active` **unverändert**. Das Altsystem schaltete Fahrzeuge bei blockierenden Mängeln selbst aus; im Neubau ist `is_active` nur der Admin-Schalter, die Einsatzfähigkeit wird aus offenen blockierenden Mängeln abgeleitet. Solche Fahrzeuge bleiben nach dem Import also inaktiv, auch wenn der Mangel später gelöst wird. Der Bericht nennt sie ("N inactive vehicle(s) have an open blocking defect …"); bei Bedarf von Hand einschalten. Weiter: `rd_type` → `service` (außerhalb 0 bis 3 → 0, Warnung), `priority` → `sort_order`, `kennzeichen` leer → `null`, `current_status` → `fms_status` (Werte über 6 bleiben als Text, Warnung), `status_source` → `fms_status_source`, `stationierung_poi_id` über `legacy_id_map` (fehlt der POI: ohne Wache, Warnung). Doppelte `name`/`identifier` bleiben alle erhalten (je eine Warnung); das EMD nahm im Altsystem die erste Zeile.
- **Erlaubte Jobs:** die Kommaliste wird wie im Fahrzeugformular zur Liste (getrimmt; doppelte ohne Groß-/Kleinschreibung, Jobs über 100 Zeichen und mehr als 50 Jobs entfallen; leer → alle Jobs). **Verhaltensänderung:** das Altsystem verglich mit `FIND_IN_SET` ohne Trimmen, "ems, fire" ließ den Job `fire` also nicht zu, nach dem Import schon. Betroffene Fahrzeuge zählt eine Warnung ("allowed_jobs had spaces around the commas"). Ebenso: Zeilenumbrüche trennen jetzt Jobs (das Altsystem las "ems⏎fire" als **einen** Job; Warnung), und eine nicht leere Liste ohne verwertbaren Job (nur Kommas, oder nur ein Job über 100 Zeichen) wird zu "alle Jobs" (Warnung; im Altsystem passte kein bzw. nur dieser eine Job).
- **Taktisches Zeichen:** die sieben Spalten werden zu `tactical_symbol`, `tz_name` → `tactical_symbol_name`. Nur Werte der Bibliotheks-Allowlist (`resources/js/lib/tacticalSymbolOptions.json`) bleiben; unbekannte Werte (darunter die acht Altwerte, die die Bibliothek nicht kennt: Fachaufgabe `versorgung`, `werkstatt`, Einheit `verband`, `groesserer-verband`, Symbol `angriff`, `bereitstellung`, `boot`, `erkunden`) werden **ohne Ersatz** verworfen, eine Warnung je Feld und Wert. Freie Texte (`typ`, `text`, `tz_name`) ohne NUL und `]]>`, höchstens 100 Zeichen (länger: gekürzt, Warnung).
- **Mängel** (`vehicle_defect`): Kategorien 1:1 auf die neuen Schlüssel (`bremsen` → `brakes` …), unbekannt → `other` (Warnung mit Wert); `vehicle_operable` → `is_operable`. `reported_by` 0 (Besatzung ohne Konto) oder ein nicht übernommenes Konto → leer; der Name kommt dann aus dem Verlaufstext "(Gemeldet durch: …)" oder dem Namen des alten Kontos (`reporter_name`), sonst bleibt er leer. `assigned_to`/`resolved_by` ohne übernommenes Konto → leer (Warnung). Nur gelöste Mängel behalten `resolved_by`, `resolved_at` und `resolution_note` (ein im Altsystem wieder geöffneter Mangel behielt sie, der Neubau leert sie beim Wiedereröffnen); eine leere Notiz wird `null`. Mängel nicht übernommener Fahrzeuge zählen als `skipped`.
- **Mangel-Verlauf** (`vehicle_defect_event`): `user_id` 0 → leer, `action` bleibt (auch `vehicle_disabled`/`vehicle_enabled`, die der Neubau nicht mehr schreibt).
- **Beladelisten** (`loadout`): `type` → `compartment` (außerhalb 0 bis 2 begrenzt, Warnung), `priority` → `sort_order`, `veh_type` → `vehicle_type`, `amount` → `quantity` (negativ → 0). Kategorien ohne Fahrzeugtyp gelten für alle Typen (Warnung): so zeigte sie schon die eNOTF-Fahrzeuginfo des Altsystems; nur die Fahrzeugseite und Vorschau der Verwaltung zeigten sie bei keinem Fahrzeug. Ein im Altsystem in eine andere Kategorie verschobener Gegenstand wandert beim nächsten Lauf mit.
- **TZ-Vorlagen** (`tactical_symbol_template`): Namen getrimmt, höchstens 100 Zeichen, eindeutig ohne Beachtung von Groß-/Kleinschreibung **und** Akzenten (die erste alte Zeile gewinnt, weitere `skipped`); eine noch nicht zugeordnete Vorlage gleichen Namens in der neuen Instanz wird übernommen (Hinweis). Symbolwerte wie bei Fahrzeugen; Vorlagen ohne Grundzeichen oder ganz ohne bekannte Werte bleiben erhalten.
- **Register** (`vehicle_registry`): nur entschiedene Einträge als Verlauf; `raw_data` → `payload`, ungültiges JSON → leer (Warnung); `processed_by` ohne Konto → leer.
- **Audit-Kontext** (`vehicle_audit_context`): `audit` übernimmt `context` unverändert, die Einträge des Moduls "Fahrzeuge" tragen danach noch alte IDs. Dieser Schritt schreibt `context.id` (Fahrzeug) und `context.defect_id` über `legacy_id_map` als Zahl um, damit der Reiter "Aktivität" der Fahrzeugseite sie findet; die alten Werte stehen in `context.legacy_id` bzw. `context.legacy_defect_id`, jeder Lauf rechnet von dort (wiederholbar). Ist das Fahrzeug nicht übernommen, entfällt `context.id` (Warnung, `skipped`). Der Text-Rückfall des Altsystems ("… [ID: n]" in Einträgen ohne Kontext) wird **nicht** übernommen: solche alten Einträge stehen im Audit-Log, aber nicht auf der Fahrzeugseite. Läuft `vehicle_audit_context` nicht mit (z. B. `--only=audit`, oder eine Abhängigkeit scheitert), behalten die Einträge die alten IDs und eine Fahrzeugseite zeigt dann womöglich den Verlauf eines **anderen** Fahrzeugs (dessen neue ID zufällig gleich ist). Der Bericht warnt in diesem Fall ("vehicle_audit_context did not run"); dann den Import mit `vehicle_audit_context` oder ohne `--only` wiederholen.

### Fahrtenbuch

- **Fahrten** (`logbook`, Tabelle `intra_fahrtenbuch` → `logbook_entries`, braucht `vehicle` und `user`): `datum`, `abfahrt` und `ankunft` bleiben als Wanduhrzeit unverändert (auch über Mitternacht); `created_at`/`updated_at` sind Zeitstempel (Instants). `fahrttyp` verliert die Endung (`einsatzfahrt` → `einsatz`, `bewegungsfahrt` → `bewegung`, `werkstattfahrt` → `werkstatt`, `uebungsfahrt` → `uebung`, `dienstfahrt` → `dienst`, `sonstige` bleibt), unbekannt → `sonstige` (Warnung mit Wert). Das Fahrzeug kommt über die Zuordnung `vehicle`; fehlt es (gelöscht oder nicht importiert), bleibt `vehicle_id` leer und `vehicle_identifier` erhalten (Warnung); ein solcher Eintrag lässt sich später ohne Fahrzeugwahl bearbeiten. `created_by` über `user`, sonst leer (Warnung). `source` unbekannt → `admin` (Warnung), `kilometer` negativ oder leer → 0 (Warnung nur bei negativ), `stationierungsort` → `station_name` (leer → nicht gesetzt), `grund` → `reason`, `fahrer_name` → `driver_name`. Zeilenfehler betreffen nur die Zeile; ein zweiter Lauf schreibt dieselben Zeilen.

### Wissensdatenbank

Entität `kb` (`App\Import\KnowledgeBaseImporter`, braucht `user`), läuft nach `form` und `calendar` (Links auf Anträge und Termine werden im selben Lauf aufgelöst) und vor `notification` und `dashboard`. Warnungen wie bei den Fahrzeugen (eine je Art mit den ersten 20 alten IDs).

- **Kategorien** (`kb_category`): Name, Icon, Reihenfolge; `slug` entfällt. Das Elternteil wird in einem zweiten Durchgang gesetzt: fehlt es (das Altsystem hatte keinen Schutz), steht die Kategorie oben (Warnung); eine Schleife (auch eine Kategorie, die ihr eigenes Elternteil ist) wird an der Kategorie mit der kleinsten alten ID aufgebrochen (Warnung). Font-Awesome-Klassen werden auf den Namen gekürzt (`fa-solid fa-pills` → `pills`), wenn er wie ein Lucide-Name aussieht, sonst kein Icon (Warnung). `sort_order` auf 0 bis 65535 begrenzt (Warnung).
- **Tags** (`kb_tag`): Namen, die sich nur in Groß-/Kleinschreibung oder Leerzeichen am Rand unterscheiden, werden **ein** Tag, auch mit einem schon vorhandenen Tag der neuen Instanz (Warnung "merged"). Ein vorhandenes Tag gleichen Namens bleibt unverändert (Farbe auch bei späteren Läufen). Farbe `#rrggbb` (klein geschrieben, `#abc` wird `#aabbcc`), sonst die Standardfarbe (Warnung). Tags ohne Namen werden übersprungen.
- **Einträge** (`kb_entry`) in zwei Durchgängen: erst alle Zeilen (damit jede neue ID feststeht), dann der Inhalt. `type` unbekannt → `general`, `competency_level` unbekannt → leer, `category_id` auf eine fehlende Kategorie → leer, `created_by`/`updated_by` über `user` (sonst leer), leerer Titel → "Eintrag <alte ID>" (je eine Warnung). `med_wirkstoff`/`med_wirkstoffgruppe` → `active_ingredient`/`drug_class`; die zwölf `med_*`/`mass_*`-Editorfelder → `sections` (Schlüssel in `KbEntry`), **auch bei einem Eintrag anderen Typs**, wenn sie Inhalt haben. `created_at`/`updated_at` sind Zeitstempel (Instants), `is_pinned`, `is_archived`, `hide_editor` bleiben. `search_text` baut `KbEntry::buildSearchText()` wie das Formular.
- **HTML → Tiptap** (`Modules\KnowledgeBase\Import\LegacyHtmlToTiptap`): nach der Alt-Allowlist (`KBHelper::sanitizeContent`): `p`, `br`, `hr`, `strong`/`b`, `em`/`i`, `u`, `s`, `h2` bis `h4` (→ Überschrift 1 bis 3; `h1` → 1, `h5`/`h6` → 3), Listen (auch verschachtelt), `blockquote`, `a`, `img`, `figure` (entpackt), Tabellen (`colspan`/`rowspan` 1 bis 999). `script`, `style`, `iframe`, `svg`, `object` usw. fallen **samt Inhalt** weg, alle anderen Elemente werden entpackt (Text bleibt); beides zählt eine Warnung mit Elementnamen und Anzahl. Attribute werden nie übernommen außer Ziel, Bildquelle/Alt-Text und Zellspannen. Links nur `http(s)://`, `mailto:` oder ein Pfad mit `/`, sonst bleibt nur der Text (Warnung). Das Ergebnis geht immer durch `KbContentValidator::normalize()`; Inhalt über 2 MB schlägt für den Eintrag fehl (die Zeile behält ihren bisherigen Inhalt).
- **Links** auf Einträge: `/lexicon/view?id=N` und `/lexicon/edit?id=N` (auch `/wissensdb/…`, mit `.php`, relativ zur Altseite wie `view?id=N`, unterhalb von `IGNIS_IMPORT_LEGACY_BASE_PATH` oder absolut auf dem Host von `SYSTEM_URL` aus `intra_config`) werden über `LegacyLinkRewriter` zu `/lexicon/<neue ID>`, auch auf Einträge, die erst später importiert werden. Ist der Eintrag nicht übernommen, bleibt nur der Text (Warnung). Andere Altseiten wie bei den Benachrichtigungen (Tabelle unten). Absolute Links auf andere Hosts bleiben.
- **Bilder:** nur `…/storage/kb-images/<32 hex>.<ext>` (mit oder ohne BASE_PATH, auch absolut auf dem `SYSTEM_URL`-Host). Mit `--uploads` wird `<PFAD>/storage/kb-images/<Name>` auf die Disk `kb-images` kopiert, unter **demselben** Namen; die Endung folgt dem erkannten Typ (ein JPEG namens `.png` wird `.jpg`). Geprüft wie beim Hochladen: Typ nach Inhalt (JPEG, PNG, WebP, GIF; kein SVG), höchstens 5 MB, Pixeldeckel; der aufgelöste Pfad (auch über Symlinks) muss im Ordner liegen. Fehlt die Datei oder wird sie abgelehnt, entfällt das Bild (Warnung mit Grund). Ohne `--uploads` bleiben Bilder, die ein früherer Lauf schon kopiert hat; die übrigen entfallen (Warnung). Fremde Quellen (`data:`, andere Hosts, andere Ordner) entfallen immer (Warnung). Beim Trockenlauf wird geprüft, aber nichts kopiert. Kopien, deren Eintrag danach scheitert, räumt `kb:images:cleanup` nach 24 h weg.
- **Tag-Zuordnungen und Beziehungen** (`kb_entry_tag`, `kb_relation`): über die Zuordnungen; fehlt eine Seite, wird die Zeile übersprungen (Warnung). Beziehungen werden einmal mit `entry_id < related_entry_id` gespeichert; Selbstbezüge und dasselbe Paar in beiden Richtungen werden übersprungen (Warnung). Beide werden nur hinzugefügt, ein zweiter Lauf verdoppelt nichts.
- **Wiederholen:** ein zweiter Lauf schreibt denselben Stand (Inhalt wird jedes Mal aus dem Alt-HTML neu umgewandelt); ein in der neuen Instanz gelöschter Eintrag kommt zurück. Zeilenfehler betreffen nur die Zeile.
- `KB_PUBLIC_ACCESS` übernimmt `system_settings` (siehe "Systemeinstellungen und Module"). Das Recht `kb.view` des Altsystems wird nicht angelegt (jedes Konto liest).

### Anträge

Entität `form` (`App\Import\FormsImporter`, braucht `user` und `personnel`), läuft nach `logbook` und **vor** `kb` (damit Links der Wissensdatenbank auf Anträge in einem Lauf aufgelöst werden), vor `notification` und `dashboard`. Warnungen wie bei den Fahrzeugen (eine je Art mit den ersten 20 alten IDs).

- **Typen** (`form_type`): Name (getrimmt), Beschreibung, aktiv, Reihenfolge (negativ → 0), `erstellt_am` als Zeitpunkt, `erstellt_von` über `user` (sonst leer, Warnung); `tabelle_name` entfällt (tot). **Seed-Typen:** die Forms-Migration legt "Beförderungsantrag" und "Urlaubsantrag" an (`DefaultTypes::NAMES`). Ein Alt-Typ ohne Zuordnung übernimmt einen noch nicht zugeordneten Typ der neuen Instanz mit demselben Namen (ohne Groß-/Kleinschreibung und Leerzeichen am Rand; Hinweis "merged into the existing type") statt ihn zu verdoppeln, **nur** wenn der Name einer dieser beiden ist und der Typ noch keine Anträge hat; dessen Werte werden mit den Altwerten überschrieben, seine Felder werden über den Schlüssel übernommen, Felder ohne Alt-Gegenstück bleiben. Jeder andere gleichnamige Typ (von Hand angelegt oder schon benutzt) bleibt unberührt, der Alt-Typ wird daneben angelegt (Warnung). **Icon:** Font-Awesome-Klasse → Lucide-Name, den die Antragsoberfläche zeichnet (`chevrons-up`, `umbrella`, `file-text`, `calendar`, …; Aliasse wie `angles-up`, `umbrella-beach`, `file-alt`), sonst kein Icon (Warnung; angezeigt wird das Dokument-Icon). **Abwesenheit:** `is_absence` nur für die Namen Urlaubsantrag, Urlaub, Freistellungsantrag, Freistellung (ohne Groß-/Kleinschreibung), und nur wenn der Typ danach die Felder `von_datum` und `bis_datum` vom Typ Datum hat; sonst aus (Warnung).
- **Felder** (`form_field`): `feldname` → `key` als Bezeichner (`^[a-z][a-z0-9_]*$`: klein geschrieben, ä/ö/ü/ß → ae/oe/ue/ss, jedes andere Zeichen → ein `_`, ohne Buchstaben am Anfang `f_` davor, höchstens 100 Zeichen; Warnung); ein im Typ doppelter Schlüssel (das Altsystem hatte keinen Unique-Index) bekommt `_2`, `_3` … nach alter ID (Warnung). Unbekannter `feldtyp` → `text`, unbekanntes `auto_fill` → keins (je Warnung). `optionen` (eine Option je Zeile, leere und doppelte entfallen) → JSON-Liste, nur bei `select`. `breite` → `width` (`half`, sonst `full`), `pflichtfeld` → `required`, `platzhalter`, `hinweistext`, `standardwert`, `readonly` 1:1; Reihenfolge nach `sortierung`, dann ID. Leeres Label → Feldname.
- **Anträge** (`form_submission`): `uniqueid` → `public_id`, wenn sechs Ziffern und in der neuen Instanz frei; sonst eine neue zufällige Nummer (gezählte Warnung "legacy id 'uniqueid' => new", erst nach erfolgreichem Schreiben; alte Links werden trotzdem umgeschrieben, Entität `form_uniqueid`). Ein schon zugeordneter Antrag behält seine Nummer. Akte über `mitarbeiter_id` und die Zuordnung `personnel`; fehlt sie, die **eine** Akte mit dieser Discord-ID (`personnel.discord_id`, Regel der Alt-Kernmigration; Warnung), sonst ohne Akte (nur Bearbeiter sehen ihn, Warnung); `discordid` bleibt in `legacy_discord_id`. **Status** (Alt `Form::STATUS_*`):

  | Alt `cirs_status` | Neu |
  |---|---|
  | 0 "In Bearbeitung" (Zustand jedes neu eingereichten Antrags), unbearbeitet | `new` |
  | 0, aber schon bearbeitet (`cirs_manager` oder `cirs_time` gesetzt, z. B. zurückgesetzt) | `in_progress` (Bearbeiter und Zeit bleiben) |
  | 1 "Abgelehnt" | `rejected` |
  | 2 "Aufgeschoben" | `deferred` (nicht offen: keine offene Aufgabe, nicht im Filter "Offen") |
  | 3 "Angenommen" | `accepted` |
  | anderer Wert (tinyint) | `in_progress` (Warnung) |

  `name_dn` → `applicant_name`, `dienstgrad` → `applicant_rank` (leer → keiner), `cirs_manager` (Name als Text) → `decided_by_name`, `decided_by` bleibt leer (ein Name ist keine verlässliche Kontozuordnung), `cirs_text` → `decision_note`. **Zwei Uhren**: `time_added` (DATETIME mit `CURRENT_TIMESTAMP`) mit der Uhr der Alt-Datenbank (`IGNIS_IMPORT_LEGACY_DB_TIMEZONE`, siehe "Zeitzone") → `submitted_at`; `cirs_time` (PHP `new DateTime()`) mit `IGNIS_IMPORT_LEGACY_TIMEZONE` → `decided_at` (ein `new`-Antrag hat nie eine).
- **Antwortdaten** (`answers`): Schnappschuss `[{key, label, type, width, value}]` aus `intra_antraege_daten` und den Alt-Felddefinitionen des Typs in Feldreihenfolge, Werte wie beim Einreichen: Kontrollkästchen als Wahrheitswert (`1`/`on`/`true` → ja, leer/`0`/`off`/`false` → nein, anderes → ja wie die Altanzeige, Warnung), sonst getrimmter Text, gekürzt auf die Grenzen des Feldtyps (Text 1000, Textfeld 10 000, E-Mail 255, Telefon/Zahl 50; Warnung). Datumswerte bleiben, wie sie sind (`Y-m-d` oder der Alttext). Werte gelöschter Felder (Waisen) werden angehängt: Label = Feldname, Typ `text`, volle Breite, bis 10 000 Zeichen (Warnung). Mehrere Werte für denselben Feldnamen: der letzte gewinnt (Warnung); Felder, die im Typ denselben Altnamen tragen (`x`, `x_2`), zeigen denselben Wert.
- **Wiederholen:** ein zweiter Lauf schreibt denselben Stand; ein in der neuen Instanz gelöschter Antrag kommt mit seiner Nummer zurück. Zeilenfehler betreffen nur die Zeile. Das Recht `application.*` übernimmt `RoleImporter` (Modul-Registry).

### Kalender

Entität `calendar` (`App\Import\CalendarImporter`, braucht `user`, `personnel`, `role` und `form`), läuft nach `form` und **vor** `kb`, `notification` und `dashboard` (deren Links `/calendar/view?id=N` brauchen die Zuordnung `calendar_event`). Blöcke zu 500, Teilnehmer und Rollen je Block in einer Abfrage. Warnungen wie bei den Fahrzeugen (eine je Art mit den ersten 20 alten IDs); Tokens erscheinen nie im Bericht oder Log.

- **Zeiten**: zeitgebundene `starts_at`/`ends_at` sind Wanduhrzeit von `IGNIS_IMPORT_LEGACY_TIMEZONE` und werden UTC; **ganztägige** (`all_day = 1`) behalten nur den Datumsteil, ohne Umrechnung (`00:00:00`, Ende inklusiv; Alt `23:59:59` des letzten Tages → dieser Tag). Ende fehlt oder liegt vor dem Beginn → Beginn (ganztägig) bzw. Beginn + 1 Stunde (Warnung). Unbrauchbarer Beginn → Zeile übersprungen. `responded_at` der Teilnehmer ebenfalls aus der PHP-Uhr; `created_at`/`updated_at` als Zeitpunkte.
- **Werte:** Titel über 160, Beschreibung über 2000 Zeichen gekürzt (Warnung; Klartext bleibt Klartext), Ort höchstens 255. Farbe `orange` → `accent`, `blue`/`green`/`red`/`purple`/`gray` gleich, unbekannt → `accent`; Kategorie `dienst` → `duty`, `general`/`meeting`/`training`/`absence` gleich, unbekannt → `general`; Sichtbarkeit `private|attendees|role|all`, unbekannt → `private` (die sicherste); je Warnung. `track_attendance` nur bei `role` (wie das Formular). `created_by` über `user`, sonst leer (Warnung).
- **Serien** werden auf die Teilmenge von `EventRequest` normalisiert, damit der Feed sich auf ihre Invarianten verlassen kann: `FREQ=DAILY|WEEKLY|MONTHLY;INTERVAL=n[;BYDAY=…][;COUNT=n]`, `UNTIL` steht in `recurrence_until`.
  - Groß-/Kleinschreibung egal; andere Teile (`BYMONTHDAY`, `X-…`, `BYDAY` außer bei WEEKLY) entfallen (Warnung). `INTERVAL` wie Alt `(int)`, mindestens 1, über 999 → 999; `COUNT` über 9999 → 9999 (Warnung).
  - **WEEKLY ohne BYDAY** (Alt zeigte die Serie täglich) bekommt den Wochentag des Beginns (Warnung "Wochenserie ohne Wochentag: Wochentag des Beginns gesetzt"); liegt der Beginn auf keinem der Wochentage, beginnt die Serie am ersten aufgeführten Wochentag ab dem Beginn (Uhrzeit in `IGNIS_TIMEZONE` und Dauer bleiben, ganztägig die Zahl der Tage; so zeigte die Alt-Ansicht das erste Vorkommen, und `COUNT` zählt dieselben Tage; Warnung "Serienbeginn auf ersten Wochentag der Serie verschoben"). Wochentag in `IGNIS_TIMEZONE`, bei ganztägigen das Datum. `INTERVAL` gilt jetzt auch bei WEEKLY (Alt ignorierte es; Warnung "Intervall wird jetzt berücksichtigt").
  - **Serien ohne Ende** (weder `COUNT` noch `UNTIL`): das Alt-System zeigte nur die ersten 366 Vorkommen ab Serienbeginn, die übernommene Serie läuft weiter (nur Warnung mit den IDs, kein Eingriff).
  - **COUNT und UNTIL** wie der Alt-Expander: `COUNT` in der Regel schlägt ein `UNTIL` in der Regel (dieses entfällt, Warnung), ein `UNTIL` in der Regel schlägt die Spalte `recurrence_until`. `COUNT` plus Spalte: es bleibt, was die Serie zuerst beendet (Warnung).
  - **UNTIL-Formate:** `YYYY-MM-DD`/`YYYYMMDD` = Ende dieses Tages in `IGNIS_TIMEZONE` (wie `EventRequest`), `YYYYMMDDTHHMMSSZ` = UTC, `YYYYMMDDTHHMMSS` oder `YYYY-MM-DDTHH:MM[:SS]` = Wanduhr in `IGNIS_TIMEZONE`; ganztägig: das Datum. Die Spalte: `00:00:00` (so speicherte das Alt-Formular ein Datum) = der ganze Tag, sonst Wanduhr der PHP-Zone.
  - **Einzeltermin statt Serie** (Warnung): Regel nicht verstanden (z. B. `FREQ=YEARLY`), `UNTIL` kein gültiges Datum, `UNTIL` vor dem Beginn, ein Vorkommen länger als 31 Tage (`CalendarEvent::MAX_SERIES_DAYS`; der Vorfilter des Feeds hängt daran), Zeile mit `parent_event_id` (Serienausnahme, im Alt nie angelegt).
- **Abwesenheiten** (`source = antrag`) werden **nicht** übernommen (als `skipped` gezählt, Warnung; eigene Warnung, wenn der Antrag gar nicht übernommen ist). Stattdessen erzeugt der Importer am Ende seines Laufs die Spiegel aus den übernommenen Anträgen neu (`AbsenceSync::backfill()`, derselbe Kern wie `calendar:backfill-absences`): angenommene Anträge von Abwesenheitstypen → ein schreibgeschützter Termin ohne Urlaubsgrund, veraltete Spiegel (Antrag nicht mehr angenommen, z. B. nach einem erneuten Import) werden entfernt. Das geschieht unabhängig vom Modulschalter zur Importzeit (`module_switch` läuft später); ein Probelauf zählt nur. Bericht: Hinweis "Abwesenheitstermine aus Anträgen erzeugt/aktualisiert/entfernt: N/N/N". `calendar:backfill-absences` bleibt als Reparaturwerkzeug. Der Schritt läuft auch, wenn die Alt-Tabellen des Kalenders fehlen (Plugin nie installiert; dann ohne Termine, aber mit Spiegeln aus den übernommenen Anträgen). Fehlt das Forms-Modul (Klasse nicht da), entfällt der Schritt mit einem Hinweis; scheitert er, zählt der Bericht ihn als eigene Entität `calendar_absence` (`read` 1, `failed` 1), die Termine bleiben übernommen. `source_ref_id` entfällt.
- **Teilnehmer:** Akte über `personnel` (fehlt sie: Zeile verworfen, Warnung), `response` außerhalb von pending/accepted/declined/tentative → `pending` (Warnung), `is_organizer` 1:1; es werden keine Zeilen erfunden. Zähler `calendar_attendee`: `read` = `written` + `skipped` (verworfen oder Termin übersprungen) + `failed` (mit ihrem Termin). **Rollen:** über `role`, fehlende Rolle verworfen (Warnung).
- **iCal-Abo**: `intra_users.ical_token` → `users.calendar_token_hash` = SHA-256 des Klartexts für das zugeordnete Konto; bestehende Abos laufen weiter (auch unter `/api/v1/…` und `/api/kalender/…`). Nur 20 bis 64 Kleinbuchstaben-Hex (sonst Warnung, das Abo muss neu erzeugt werden); Konto nicht übernommen → Warnung; Hash schon bei einem anderen Konto → der erste gewinnt (Warnung); hat das Konto in der neuen Instanz schon ein anderes Abo, bleibt es (Warnung, nie still überschrieben). Je Konto nur **einmal** übernommen (Entität `calendar_token`): ein später ersetztes oder widerrufenes Token kommt bei einem weiteren Lauf nicht zurück, ein im Altsystem später geändertes Token auch nicht.
- **Wiederholen:** ein zweiter Lauf schreibt denselben Stand (Termine über `calendar_event`, Teilnehmer über Termin und Akte, Rollen-Pivot wird ergänzt, nie gelöscht; gelöscht werden nur veraltete Abwesenheits-Spiegel); ein gelöschter Termin kommt zurück. Zeilenfehler betreffen nur den Termin (samt Teilnehmern und Rollen). Die Rechte `calendar.*` übernimmt `RoleImporter` (Modul-Registry).

### MANV-Board

Entität `manv` (`App\Import\ManvImporter`, braucht `user`, `personnel`, `account_link`, `vehicle` und `poi`), läuft nach `calendar` und **vor** `kb`, `notification` und `dashboard` (deren Links `/mci/board?id=N`, `/mci/patient-view?id=N` brauchen die Zuordnungen `manv_incident`/`manv_patient` im selben Lauf). Reihenfolge Lagen → Ressourcen → Patienten → Log, je Tabelle in Blöcken zu 500. Warnungen wie bei den Fahrzeugen (eine je Art mit den ersten 20 alten IDs).

- **Uhren**: `erstellt_am`, `geaendert_am`, Log-`timestamp` und `transport_abfahrt` sind Datenbankuhr (`IGNIS_IMPORT_LEGACY_DB_TIMEZONE`); `einsatzbeginn` und `sichtungskategorie_zeit` sind PHP-Uhr (`IGNIS_IMPORT_LEGACY_TIMEZONE`). `geburtsdatum` bleibt Datum (`0000-00-00` und Unlesbares → leer, Warnung).
- **Lagen** (`manv_incident`): `lna_mitarbeiter_id`/`orgl_mitarbeiter_id` sind **Konto**-IDs (Altfehler 1.4-10): Konto über `user` → `users.personnel_id` → Akte. Ohne Akte (Konto nicht übernommen oder nicht verknüpft) bleibt nur der Name (Warnung). Der Alt-Name (kam aus dem Browser) bleibt **unverändert**, auch wenn er von der Akte abweicht; nur ein leerer Name wird aus der Akte gefüllt. Status `aktiv`/`abgeschlossen`/`archiviert` → active/closed/archived, unbekannt oder leer → active (Warnung). `einsatzende` bleibt leer (das Altsystem schrieb es nie; ein Wert wird gemeldet). Ohne `einsatzbeginn` gilt `erstellt_am` (Warnung).
- **Konten** (`erstellt_von`, `geaendert_von`, `sichtungskategorie_geaendert_von`, Log-`benutzer_id`) über `user`, sonst leer (Warnung je Spalte, gezählt). Log-`benutzer_name` (im Altsystem praktisch immer leer, 1.4-3): Alt-Text, sonst der Name des Kontos (Akte, sonst Kontoname), sonst leer (Anzeige "System").
- **Ressourcen** (`manv_resource`): `typ` fahrzeug/personal/material → vehicle/personnel/material, `status` verfuegbar/im_einsatz/nicht_verfuegbar → available/deployed/unavailable (unbekannt → vehicle/available, Warnung). Bezeichnung je Lage eindeutig (ohne Groß-/Kleinschreibung und Leerzeichen am Rand, wie die `_ci`-Sortierung des Altsystems): Dubletten → "Bezeichnung (2)", "(3)" nach ID (Warnung). `vehicle_id` nur, wenn **genau ein** aktives Fahrzeug so heißt; mehrere → ohne Fahrzeug (Warnung), keins → ohne (frei angelegte Ressource, keine Warnung). `besatzung` über 255 Zeichen wird gekürzt, der volle Text an `notes` angehängt (Warnung). Bei einer Dublette "(2)" behält nur die erste Ressource das Bestandsfahrzeug (Warnung). Importierte Ressourcen haben immer `departed_at = null`, auch wenn nur abgefahrene Patienten auf sie verweisen (das Altsystem kannte keine Abfahrt der Ressource, es löschte sie).
- **Patienten** (`manv_patient`): Nummern je Lage eindeutig (1.4-5): Dubletten → `-2`, `-3` nach ID (Warnung). Sichtung `tot` → `SK5`, leerer ENUM-Wert (`''` eines nicht strikten Servers) → ungesichtet (Warnung); Geschlecht `w` → `f`, leer → unknown (Warnung). Ressource über `transportmittel_rufname` = Bezeichnung **derselben** Lage (erste nach ID); fehlt sie (Abfahrt hat sie gelöscht, 1.4-4, oder umbenannt), bleibt nur der Schnappschuss `callsign`/`vehicle_type`/`vehicle_location` (Warnung, eigene für Abgefahrene). `transport_abfahrt` → `departed_at`. `transportziel` bleibt Text; `destination_poi_id` nur, wenn genau eine POI vom Typ `Krankenhaus` so heißt. `massnahmen` (kein Feld mehr) und `transport_ankunft` (gestrichen) werden an `notes` angehängt ("Maßnahmen (Altbestand): …", "Ankunft (Altbestand): …", Warnung), nie verworfen.
- **Log** (`manv_log`): `aktion` und `beschreibung` unverändert; `referenz_typ` patient/ressource → patient/resource mit der **neuen** ID; fehlt der Datensatz (Ressourcen nach Abfahrt gelöscht), bleibt die Referenz leer und der Text steht (Warnung). Ohne `timestamp` gilt `erstellt_am` der Lage (Warnung).
- **Rechte:** `mci.manage` übernimmt `RoleImporter` (Modul-Registry); Altstände vor der Kern-Migration `20260505000004` mit `manv.manage` werden auf `mci.manage` abgebildet. Das neue Leserecht `mci.view` vergibt der Import **niemandem**.
- **Wiederholen:** über `legacy_id_map` (auch Logzeilen, Entität `manv_log`); ein zweiter Lauf schreibt denselben Stand, ein gelöschter Datensatz kommt zurück, nichts wird gelöscht. Zeilen, deren Lage nicht übernommen ist, werden übersprungen (gezählt); ein Zeilenfehler betrifft nur die Zeile. Kollidiert eine Patientennummer mit einem in der neuen Instanz angelegten Patienten derselben Lage, scheitert nur diese Zeile. **Vergleiche** (Fahrzeug-, Klinik-, Bezeichnungs- und Nummernabgleich) falten Groß-/Kleinschreibung und Leerzeichen am Rand, aber **keine Akzente**; MariaDB mit `utf8mb4_unicode_ci` setzt "é" und "e" gleich, der Importer nicht (dann bleibt die Ressource ohne Fahrzeug oder bekommt "(2)", jeweils mit Warnung). **Prüfung nach dem Lauf:** Warnungen zu `tot`→`SK5`, doppelten Nummern und Bezeichnungen, Ressourcen ohne Fahrzeug und Konten ohne Akte lesen; ein zweiter Lauf muss denselben Stand liefern (Test `tests/Feature/Import/ManvImportTest.php`, Gruppe `legacy`).

### FireTab

Entität `firetab` (`App\Import\FireTabImporter`, braucht `user`, `personnel` und `vehicle`), läuft nach `manv` und **vor** `notification` und `dashboard` (deren Links `/firetab/view?id=N` brauchen die Zuordnung `fire_incident` im selben Lauf); `--only=firetab` zieht die Abhängigkeiten mit. Teil 1: Einsätze → Fahrzeuge → Lagemeldungen → Log; Teil 2: Atemschutz-Trupps → Mitglieder → Ereignisse → Alt-Protokolle; Teil 3: Kartenmarker → Kartenzonen. **Jede Tabelle in Blöcken zu 500** (`chunkById`), **eine Transaktion je Block**, ein Sicherungspunkt je Zeile (Zuordnung im Zeilen-`try`): eine fehlerhafte Zeile wird allein zurückgerollt. Warnungen je Art mit den ersten 20 alten IDs.

- **Vorprüfung:** die Altinstanz muss die Kern-Migration `20250607000122` (Zeitzonen-Fix) in `phinxlog` haben, sonst bricht der **ganze** Lauf vor dem ersten Schreiben ab (`php cli/intra.php migrate` im Altsystem, oder `firetab` per `--only` weglassen). Ohne die Migration wären `started_at` und lokale Lagemeldungen Berliner Zeit.
- **Uhren**: `started_at` und `report_time` sind schon **UTC** und werden **unverändert** übernommen (nicht über `IGNIS_IMPORT_LEGACY_TIMEZONE`). Alle `TIMESTAMP`-Spalten (`created_at`, `updated_at`, `finalized_at`, `archived_at`, `status_updated_at`) sind Zeitpunkte. **Zeiten der Karte:** `created_at` der Marker und Zonen war erst `DATETIME` und ist seit den Alt-Kernmigrationen `20250607000090`/`…091` ein `TIMESTAMP` (geschrieben mit `NOW()`): Zeitpunkt über die Datenbankuhr (`UNIX_TIMESTAMP`, `tableWithInstants`), → `created_at` und `updated_at`. **Sonderfall** EMD-Einsätze (`created_by` leer und Log `created` "Einsatz automatisch durch Sync erstellt"): ihr `created_at` war UTC-Text in einer `TIMESTAMP`-Spalte; er wird als Wanduhr der Altdatenbank (`IGNIS_IMPORT_LEGACY_DB_TIMEZONE`) gelesen und als UTC genommen, ein Hinweis nennt die Anzahl.
- **Einsätze** (`fire_incident`): `incident_number` wörtlich (auch "BITTE ÄNDERN!"); `status` 0 bis 4 → new/reviewing/approved/insufficient/hidden, sonst new (Warnung); `leader_id` über `personnel` (fehlt: leer, Warnung); `created_by`, `updated_by`, `finalized_by`, `archived_by` über `user` (0, nicht übernommen oder veralteter Zuordnungseintrag: leer, Warnung je Spalte); `finalized`/`archived` = 1 ohne Zeit → `updated_at` (Warnung), = 0 → leer; `owner_type` (das Altsystem schrieb nie einen) wird an `notes` angehängt (Warnung).
- **Fahrzeuge** (`fire_incident_vehicle`): `vehicle_id` über `vehicle`; fehlt es, bleibt der Text-Schnappschuss als **Fremdfahrzeug** (`is_external`, Warnung). Dubletten (Einsatz, Fahrzeug) aus EMD-Rennen werden zusammengeführt: es bleibt die Zeile mit dem **jüngsten Status** (`status_updated_at`, dann höchste ID), die übrigen werden gezählt übersprungen (Warnung "merged into legacy row N"), damit der Unique-Index hält. `current_status` bleibt Text (auch `N`, `#`, `C`).
- **Lagemeldungen** (`fire_sitrep`): `source` leer → local, `leitstelle` → dispatch, sonst local (Warnung); `vehicle_radio_name` → `reporter_name`; `is_important` = false. **`synced_at` = Importzeit für alle Zeilen**, auch nie übertragene lokale (sonst schickt der EMD-Sync den Altbestand erneut an die Leitstelle); ein weiterer Lauf behält den Wert.
- **Log** (`fire_incident_log`): `action_type` als Text (unbekannte Schlüssel gezählt), `vehicle_id`/`operator_id` über `vehicle`/`personnel`, Waisen leer (Warnung); `created_by` 0 oder leer → leer (Systemeintrag), nicht übernommen → leer (Warnung).
- **Status-Warteschlange** wird **nicht** übernommen (flüchtig): zugestellte Zeilen entfallen, nicht zugestellte werden gezählt (Warnung).
- **Atemschutz** (Teil 2): alle Tabellen 1:1 in ID-Reihenfolge. Fehlen die neuen Alttabellen (Altmigration `20261011100001` nicht gelaufen), werden Trupps, Mitglieder und Ereignisse mit einem Hinweis übersprungen; die Alt-Protokolle laufen trotzdem.
  - **Trupps** (`fire_asu_trupp`): Einsatz über `fire_incident` (fehlt: übersprungen, gezählt); `vehicle_id` über `vehicle` (nicht übernommen oder veralteter Zuordnungseintrag: leer, Warnung); unbekannte Rolle → `angriff` (Warnung).
  - **Mitglieder** (`fire_asu_member`): Trupp über `fire_asu_trupp` (fehlt: übersprungen); `mitarbeiter_id` → `personnel_id` über `personnel` (fehlt: leer, Warnung); unbekannte Position → Zeile scheitert.
  - **Ereignisse** (`fire_asu_event`): Trupp über `fire_asu_trupp` (Waise: übersprungen, gezählt), `member_id` über `fire_asu_member` (fehlt: leer, Warnung); `client_uuid` unverändert (neu eindeutig je Einsatz); `created_at` (Serverzeit, Instant über die DB-Uhr) → **`occurred_at` und `received_at`**; `voided_at` bleibt (annullierte Ereignisse bleiben annulliert, `voided_by` leer, das Altsystem kannte keinen Annullierer); die Mayday-Notiz (JSON) bleibt wörtlich; ein unbekannter Ereignistyp lässt die Zeile scheitern (Bericht "Failures", Exit-Code 1, die übrigen Zeilen laufen weiter).
  - **Alt-Protokolle** (`fire_asu_protocol`, `intra_fire_incident_asu`): `data` unverändert → `payload`; Unique (Einsatz, Überwacher) wie im Altsystem; `timestamp` ist UTC-Wanduhr (so gespeichert) → `recorded_at`; `mission_date` als Datum.
- **Lagekarte** (Teil 3): Einsatz über `fire_incident` (fehlt: übersprungen, gezählt). Fehlt eine der beiden Alttabellen, wird sie mit einem Hinweis übersprungen.
  - **Zuordnungen** (Marker und Zonen): `created_by` ist eine **Konto**-ID, obwohl der Alt-Fremdschlüssel auf `intra_mitarbeiter` zeigte (die Altanzeige hat deshalb den Namen der Akte mit derselben Nummer gezeigt, also oft einen **falschen** Namen) → `created_by_user_id` über `user`; `operator_id` → `personnel_id` über `personnel`; `vehicle_id` über `vehicle`. Nicht übernommen oder veralteter Zuordnungseintrag → leer (Warnung je Spalte, gezählt).
  - **Marker** (`fire_map_marker`): `pos_x`/`pos_y` auf 0 bis 100 geklemmt, 2 Nachkommastellen (Warnung beim Klemmen); `marker_type` außerhalb der Legende → `custom` (Warnung, `description` bleibt unverändert), `vehicle_<alt>` → `vehicle_<neu>` (Fahrzeug nicht übernommen → `custom`, Warnung); Felder des taktischen Zeichens über 100 Zeichen gekürzt (Warnung, die Zeile scheitert nie daran); die Symbolfelder laufen wie bei den Fahrzeugen über `VehicleImporter::symbol` (`TacticalSymbol::clean`, nur Werte der Bibliothek bleiben, unbekannte entfallen mit gezählter Warnung; der Alt-Einsatzort-Marker hatte `feuer`, das die Bibliothek nicht kennt).
  - **Zonen** (`fire_map_zone`): `points` muss eine JSON-Liste von mindestens 3 `{x, y}` mit Zahlen in 0 bis 100 sein (Werte auf 2 Nachkommastellen); sonst wird die Zone **trotzdem übernommen**, mit `is_valid = false` (nie gezeichnet, nicht verworfen; der Alttext bleibt als JSON bzw. JSON-Zeichenkette), Warnung. Farbe nicht `#rrggbb` → `#dc3545` (Warnung), sonst klein geschrieben. Gültige Farbe außerhalb der 9 Formularfarben bleibt (gezählte Warnung). Name über 255 Zeichen gekürzt (Warnung).

- **Verteiler** (`mail_list`): Regel `role_ids` → `role`, `rank_ids` → `rank`, `rd_quali_ids` → `ems_qualification`, `fw_quali_ids` → `fire_qualification`, `fachdienst_ids` → `specialty` über die Zuordnungen; nicht abbildbare IDs fallen weg (Warnung); ein dynamischer Verteiler mit leerer Regel bleibt und stellt nichts zu (Warnung). Rollenregel: neu zählt **irgendeine** Rolle des Kontos (Obermenge; Hinweis). Unbekannte Art → statisch, unbekannte Absenderregel → `managers` (Warnung).
- **Nachrichten** (`mail_message`) in ID-Reihenfolge: Absenderpostfach und schreibendes Konto über die Zuordnungen (ohne Absenderpostfach übersprungen), `thread_id` unverändert (länger als 32 Zeichen oder nicht alphanumerisch → ihr MD5, Warnung), `header_json` mit den Adressen unverändert (wörtlich übernommen; BCC bleibt dort, angezeigt nur über `visibleHeader`), aber in die Form `{to, cc, bcc}` je Liste von Texten gebracht (`MailImporter::header`: Text ⇒ Liste mit einem Eintrag, fehlender Schlüssel ⇒ leer; Nicht-Texte und fremde Schlüssel fallen weg, unlesbarer Kopf ⇒ leer, jeweils gezählte Warnung). `in_reply_to` auf eine ältere ID sofort, auf eine neuere im zweiten Durchgang; fehlt das Original, bleibt es leer (Warnung). **Inhalt**: `body_json` läuft durch den strengen `MailContentValidator`, nachdem Bilder auf den Abzeichenpfad des gleichen Dienstgrads der neuen Instanz umgeschrieben (Alt-`BASE_PATH`, `?v=`, `public/` und absolute URLs auf dem Alt-`SYSTEM_URL`-Host werden erkannt) oder entfernt (Warnung) und Links auf das Altsystem über `LegacyLinkRewriter` auf `APP_URL` umgeschrieben wurden (fremde Links bleiben, unbrauchbare fallen weg, der Text bleibt). Lehnt der Validator ab, werden **Absätze aus dem Klartext von `body_html`** übernommen (Entwürfe ohne `body_html`: aus dem Text des JSON; höchstens 100 000 Byte; gezählte Warnung). `body_html` wird **nie** gespeichert, die Anzeige rendert neu; `search_text` (Betreff + Klartext) wird gebaut. Links im Mailtext auf andere Mails lösen auf, wenn die (ältere) Mail in einem früheren Block lag, sonst beim nächsten Lauf. Entwürfe älter als 30 Tage übernimmt der Import und überlässt sie `mail:cleanup`.
- **Zustellungen** (`mail_delivery`) vollständig: Ordner, Rolle, `read_at`, Fahne, **`deleted_at`** (gelöschte Kopien bleiben gelöscht); `sorted_at` = `sent_at`, sonst `updated_at`, sonst `created_at` der Nachricht. Unbekannte Rolle oder unbekannter Ordner → die Zeile **scheitert** (Warnung). Über (Nachricht, Postfach, Rolle) wiederholbar.
- **Anhänge** (`mail_attachment`) **nur mit `--uploads`** (sonst gezählt übersprungen, Hinweis), Quelle `<uploads>/storage/private/mail-attachments`. Der Altpfad muss `[storage/private/mail-attachments/]mail-<id>-<16 hex>.<ext>` sein, die Datei per `realpath` direkt in diesem Ordner liegen (kein Symlink nach draußen), höchstens 5 MB haben und nach **Magic Bytes** ein erlaubter Typ sein (PNG, JPEG, WebP, GIF, PDF, Text; kein SVG/HTML). Dann wird sie mit **neuem Namen** (`mail-<neue Nachricht>-<16 hex>.<ext>`) auf die private Disk `mail-attachments` (`storage/app/private/mail-attachments`) kopiert; gespeichert werden der erkannte Typ (weicht er vom Alttyp ab: Warnung) und ein Anzeigename mit passender Endung. Fehlt die Datei oder wird sie abgelehnt (Muster, Größe, Typ, Ordner fehlt), **bleibt die Zeile** mit `missing = true` (Download 404, Warnung je Grund; Typ `application/octet-stream`, wenn der Alttyp nicht erlaubt ist). Hat ein früherer Lauf die Datei schon kopiert und liegt die Kopie noch auf der Disk, bleibt diese Zeile unverändert, auch wenn die Altdatei inzwischen fehlt oder `--uploads` auf einen falschen Ordner zeigt (Warnung "the copy of an earlier run is kept"; sonst würde `mail:cleanup --prune-orphans` die Kopie löschen). Ein weiterer Lauf kopiert eine schon kopierte Datei mit gleichem Inhalt nicht erneut (geänderter Inhalt: neue Kopie, die alte bleibt als Waise für `mail:cleanup --prune-orphans`). Dateien im Altordner ohne Zeile werden **gezählt**, nicht kopiert (Warnung). Der Probelauf prüft, kopiert aber nichts.
- **Signaturen** (`mail_signature`): Links auf das Altsystem werden wie im Mailtext über `LegacyLinkRewriter` auf `APP_URL` umgeschrieben (auch in `MAIL_DEFAULT_SIGNATURE`); dann je Postfach über `SignatureTemplate::parse` (nur Absätze, Text, Umbruch, bekannte Platzhalter, vier Marks); abgelehnt → Klartext je Block (Warnung). `MAIL_DEFAULT_SIGNATURE` (Editor-JSON oder Alt-Klartext, eine Zeile je Absatz) wird über `SignatureTemplate::saveDefault` die **eine** Standardzeile (`mailbox_id` NULL; gleich der eingebauten Vorlage oder leer: keine Zeile). Wie bei Einstellungen: hat die neue Instanz schon eine andere Standard-Signatur, bleibt sie (Hinweis), außer mit `--overwrite-settings`.
- **Einstellungen** (`mail_setting`, "der Erste gewinnt" wie alle Einstellungen): `MAIL_DOMAIN` → `mail.domain` (klein geschrieben; ungültig → nicht übernommen, Warnung), `MAIL_ADDRESS_PATTERN` → `mail.address_pattern` (`initial_dot_last`/`first_dot_last`, sonst Warnung), `MAIL_ALLOWED_DOMAINS` (Komma) → `mail.allowed_domains` (ungültige Einträge fallen weg, Warnung), `MAIL_SEND_COOLDOWN` → `mail.send_cooldown` (0 bis 3600 Sekunden, größer → 3600, Warnung). Die Cron-Zeilen `mail.backfill`/`mail.cleanup` werden nicht übernommen: das Modul plant `mail:backfill` (03:15) und `mail:cleanup` (03:30) selbst.
- **Rechte:** `mail.use`, `mail.lists.manage`, `mail.domain.choose`, `mail.admin` registriert das Modul; `RoleImporter` übernimmt sie unverändert (keine Warnung "unknown permission").
- **Alt-URLs** (`LegacyUrlMap::mailRedirect`): Die Altpfade haben dieselbe Form wie die neuen Routen (`/mail/{folder}/{id}`, `/mail/compose/{reply,reply-all,forward,draft}/{id}`, `/mail/lists/{id}/edit`, `/settings/mail/mailboxes/{id}/edit`, `/mail/attachments/{id}`). Deshalb wird nur eine **Altanfrage** umgeleitet: mit `?postfach=N` (das Altsystem hängte es an jeden Link im Arbeitsbereich, der Neubau nutzt `?mailbox=`) oder mit `.php`. Dann 301 auf die neue ID (`mail_message`, `mail_attachment`, `mail_list`, `mail_mailbox`; unbekannt → `/mail/<Ordner>`, `/mail`, `/mail/lists` bzw. `/settings/mail/mailboxes`) und `?postfach=N` → `?mailbox=<neu>` (nicht übernommen: entfällt); Seiten ohne ID (`/mail`, `/mail/{folder}`, `/mail/compose`, `/mail/signature`, `/mail/lists`, `/settings/mail`, …) behalten ihren Pfad. Ohne Marker antwortet die neue Route und liest die Zahl als **neue** ID: ein Lesezeichen `/mail/inbox/5` öffnet also die neue Mail 5 (sichtbar nur, wenn sie eine eigene ist, sonst 404), nicht die Alt-Mail 5. Anhang-Links des Altsystems (`/mail/attachments/N`) trugen nie `?postfach=` und werden deshalb nur mit `.php` umgeleitet. Das ist bewusst so: eine bedingungslose Umleitung würde jede neue URL brechen. `/mail/{folder}/{id}/preview` und die Alt-POST-Endpunkte gibt es nicht mehr (404/405).
- **Nach dem Import** `php artisan mail:backfill --dry-run`: es meldet nur Akten, die im Altsystem kein Postfach hatten ("N created"), und lässt importierte Postfächer, wie sie sind.
- **Wiederholen:** über `legacy_id_map` und die eindeutigen Schlüssel; ein zweiter Lauf schreibt denselben Stand (auch keine neuen Dateien), eine gelöschte Nachricht kommt mit ihren Zustellungen zurück, nichts wird gelöscht. **Prüfung nach dem Lauf:** Warnungen zu übernommenen/umbenannten Postfächern, Klartext-Fallback, entfernten Bildern, fehlenden Anhängen und gescheiterten Zustellungen lesen (Test `tests/Feature/Import/MailImportTest.php`, Gruppe `legacy`; Alt-URLs `tests/Feature/LegacyMailUrlsTest.php`). **Abschlusskontrolle 7b:** (1) Probelauf `ignis:import-legacy --only=mail --dry-run` (hinterlässt keine Spuren), dann echt mit `--uploads=<Wurzel der Altinstallation>`, sonst bleiben alle Anhänge `missing`; (2) Warnungen lesen (siehe oben) und Postfächer mit "renamed" im Bericht den Betroffenen mitteilen; (3) zweiter Lauf: derselbe Stand, keine neuen Dateien in `storage/app/private/mail-attachments`; (4) `mail:backfill --dry-run`, `mail:cleanup --dry-run`; (5) Rollen prüfen (`mail.use`, `mail.lists.manage`, `mail.domain.choose`, `mail.admin` kommen mit; `admin` und Super-Admin lesen trotzdem keine fremden Mails); (6) stichprobenartig Alt-Links mit `?postfach=` und Glockenlinks öffnen. Von den Links zeigt der Umschreiber nur auf Nachrichten (`/mail/<Ordner>/N`); Anhang-, Antwort- und Listenlinks in Alt-Texten bleiben unverändert (alte IDs).

### Vernetzung

Entität `federation` (`App\Import\FederationImporter`, keine Abhängigkeiten), läuft nach `firetab`.

- **Einstellungen** ("der Erste gewinnt"): `FEDERATION_ENABLED` → Modulschalter `modules.federation.enabled` (der Installer schreibt den Schalter aus: ohne `--overwrite-settings` bleibt er aus, Hinweis "Neusystem-Wert bleibt"), `FEDERATION_INSTANCE_ID` → `federation.instance_id` **unverändert** (die Partner kennen die Instanz an dieser ID), `FEDERATION_INSTANCE_NAME` → `federation.instance_name`.
- **Verbindungen** (`intra_federation_links` → `federation_links`, Zuordnung `federation`): Instanz-ID, Name, Adresse, alle sechs Flags, Intervall (auf 5 bis 1440 begrenzt) und aktiv unverändert; **beide Schlüssel verschlüsselt** (APP_KEY; HMAC braucht den Klartext, Hashen geht nicht); `confirmed_at` leer, Cursor leer, Status `pending`; der Alt-Fehlertext wird nicht übernommen (er kann Antwortinhalt enthalten). Laufen beide Seiten auf dem Neusystem, funktioniert die Verbindung ohne neue Kopplung (gleiche Schlüssel beidseitig, Protokoll v2); eine Gegenstelle auf dem Altsystem meldet `peer_v1`. Warnung mit Anzahl und Instanznamen (nie Schlüssel); Adressen ohne https gezählt (Abruf meldet `invalid_url`); hat die neue Instanz dieselbe Instanz-ID schon gekoppelt, bleibt deren Verbindung (Warnung).
- **Caches und Sync-Log** (`intra_federation_cache_{personnel,enotf,fire}`, `intra_federation_sync_log`): nur gezählt (Hinweis), beim ersten Abruf neu geladen.
- **FireTab-Leiter aus dem Verbund:** nichts nachzutragen; das Altsystem konnte `fed:`-Leiter nicht speichern (`leader_id` INTEGER mit Fremdschlüssel).
- **Wiederholen:** über `legacy_id_map`; ein zweiter Lauf schreibt denselben Stand (Schlüssel neu verschlüsselt). Probelauf ohne Spuren. Test `tests/Feature/Import/FederationImportTest.php` (Gruppe `legacy`).

### Benachrichtigungen, Schnellzugriffe, Ankündigungen

Warnungen wie bei den Fahrzeugen: eine je Art mit Anzahl und den ersten 20 alten IDs; `read` = `written` + `skipped` + `failed`.

- **IDs der Benachrichtigungen** (`notification`): `notifications.id` ist eine UUID. Jede Zeile bekommt eine **UUID Version 5** (RFC 4122, SHA-1) aus dem festen Namensraum `00747f74-9f52-4135-b143-e67a702d6e73` und dem Namen `intra_notifications:<alte ID>` (`App\Import\NotificationImporter::uuid`). Jeder Lauf erzeugt also dieselben IDs und aktualisiert statt zu duplizieren (Block-Upsert über `id`, scheitert ein Block, Zeile für Zeile). Der Namensraum darf sich nie ändern.
- **Empfänger und Typ:** `user_id` über `legacy_id_map` (Entität `user`); fehlt das Konto, wird die Zeile übersprungen (gezählt). `type` bleibt der Altschlüssel. Typen, die (noch) nicht registriert sind (unbekannte oder von keinem Modul registrierte), werden trotzdem übernommen und je Typ gemeldet; die Inbox zeigt sie mit dem Rohschlüssel **jedem Empfänger**, bis das Modul den Typ registriert (erst dann greift dessen Sichtbarkeitsregel).
- **Inhalt:** `data` = `{title, message, link}`; Titel höchstens 255 Zeichen. Die Nachricht wird nur so weit gekürzt (an einer Zeichengrenze), dass das JSON in die `TEXT`-Spalte passt (65535 Byte; Anführungszeichen und Steuerzeichen werden beim Kodieren 2- bis 6-mal so lang; Warnung). Der Text bleibt in der Sprache, in der das Altsystem ihn schrieb.
- **Gelesen:** `is_read = 1` → `read_at` aus der Altspalte; fehlt sie, `read_at` = `created_at` (Warnung). `is_read = 0` → ungelesen, auch wenn `read_at` gefüllt ist. `updated_at` = der spätere der beiden Zeitpunkte. **Jeder weitere Lauf setzt den Gelesen-Status auf den Stand des Altsystems zurück**: was nach dem Import in der neuen Instanz gelesen wurde, ist danach wieder ungelesen, solange es im Altsystem ungelesen ist.
- **Uhren:** `created_at` (`DATETIME` mit `CURRENT_TIMESTAMP`) und `read_at` (mit `NOW()` gesetzt) sind Wanduhrzeit der Altdatenbank (`IGNIS_IMPORT_LEGACY_DB_TIMEZONE`, siehe "Zeitzone"). Ausnahme: für Typ `mail` gilt `IGNIS_IMPORT_LEGACY_TIMEZONE`, weil das Mail-Modul `read_at` beim Lesen einer Mail mit PHP (`date()`) setzte. **Unschärfe:** wurden Mail-Einträge über "alle gelesen" der Glocke markiert, schrieb das Altsystem `NOW()` (Datenbankuhr); welche Uhr eine Zeile hat, ist nicht erkennbar. Laufen PHP und Datenbank in verschiedenen Zonen, können diese `read_at` um die Zeitverschiebung abweichen (nur Anzeige, keine Logik hängt daran).

### Auth-Einstellungen und `discord.redirect_path`

- `API_KEY` wird **nur mit `--import-api-key`** übernommen (sonst ein Hinweis), und nur, wenn die neue Instanz noch keinen Schlüssel hat und der alte brauchbar ist (mindestens 16 Zeichen, nicht `CHANGE_ME`). Weicht ein vorhandener Schlüssel ab, wird er **nicht** überschrieben (Warnung), außer zusätzlich mit `--overwrite-settings`. Der übernommene Schlüssel ist derselbe, den `ef_bridge` schon kennt; er wird verschlüsselt gespeichert und nie im Bericht ausgegeben.
- `REGISTRATION_MODE` (`open`, `code`, `closed`; Altstandard `open`, neuer Standard `code`: der Altwert wird übernommen) und `TABLET_LOGIN_ENABLED` werden nur gesetzt, wenn die Einstellung noch nicht existiert ("Der Erste gewinnt", außer mit `--overwrite-settings`). Ein ungültiger Modus und ein Schalter, der kein Ja/Nein-Wert ist, werden verworfen (Warnung). Ja/Nein wie bei `system_settings`.
- `discord.redirect_path` wird auf `/auth/callback.php` gesetzt, weil die Discord-Anwendung des Altsystems mit dieser URI registriert ist. Danach ist die Anmeldung ohne Änderung im Discord-Portal möglich. Es bleibt unverändert, wenn die Einstellung bereits einen **anderen** Wert als den Standard `/auth/discord/callback` hat. Soll später die kanonische URI gelten: im Discord-Portal `{APP_URL}/auth/discord/callback` eintragen, dann die Einstellung zurücksetzen:
  `docker compose exec app php artisan tinker --execute="app(App\Support\Settings::class)->set('discord.redirect_path', '/auth/discord/callback');"`. Ein erneuter Importlauf setzt sie wieder auf `/auth/callback.php` (siehe "Wiederholen").

### Systemeinstellungen und Module

**Installer-Werte:** Der Installer schreibt immer `system.name` und die Modul-Schalter `modules.<name>.enabled`, und der Import läuft erst nach der Installation. Nach "der Erste gewinnt" bleiben diese Werte also stehen, der Name und die Schalter des Altsystems kommen **nicht** an; der Bericht sagt das (`SYSTEM_NAME: Neusystem-Wert bleibt; Altwert unterscheidet sich — mit --overwrite-settings übernehmen.`, bei den Modulen mit den Modulnamen). Wer die Altwerte übernehmen will, macht den **ersten** Lauf mit `--overwrite-settings`. Der Schalter ersetzt dann **jede** schon gespeicherte Einstellung, die der Import kennt, also auch Änderungen, die der Betreiber in der neuen Instanz schon gemacht hat; den API-Schlüssel nur zusammen mit `--import-api-key`.

Die Zuordnung steht in **einer** Tabelle, `App\Import\LegacyConfigMap` (je Altschlüssel: Ziel, Umwandlung, Grund); `LegacyConfigMapTest` schlägt fehl, wenn einer der Schlüssel, die das Altsystem erst zur Laufzeit schreibt (`INSTALLATION_ID`, `TELEMETRY_LAST_HEARTBEAT`, `TELEMETRY_RATE_LIMIT_UNTIL`, gelesen `FORUM_URL`), dort fehlt. Jede Zeile von `intra_config` zählt genau einmal als `written` (auch wenn der Wert schon so gespeichert ist), `skipped` oder `failed`; `read` = `written` + `skipped` + `failed`. Der Bericht nennt **nur Schlüsselnamen, nie Werte**.

| Alt | Neu | Regel |
|---|---|---|
| `SYSTEM_NAME` | `system.name` | Die Standardnamen `intraRP` und `ıgnıs` (mit punktlosem i, Rebrand-Migration `20260424000002`) gelten als nicht gesetzt. |
| `SYSTEM_COLOR` | `system.accent_color` | Ungültige Werte (alles außer `#rrggbb`) werden abgewiesen, der Standard bleibt (Warnung); Großbuchstaben werden klein geschrieben. Die Auslieferungsfarben `#d10000`, `#f0500a`, `#ff4d00` gelten als nicht gesetzt (wie im Altsystem). |
| `SYSTEM_LOGO` | `system.logo` + Datei | Siehe unten. |
| `META_IMAGE_URL`, `LEGAL_IMPRESSUM_URL`, `LEGAL_DATENSCHUTZ_URL` | `system.meta_image_url`, `legal.imprint_url`, `legal.privacy_url` | Nur `https://`; sonst Warnung, nicht übernommen. |
| `SERVER_NAME`, `SERVER_CITY`, `RP_ORGTYPE`, `RP_STREET`, `RP_ZIP` | `organisation.name`, `.city`, `.type`, `.street`, `.zip` | |
| `CHAR_ID` | `personnel.require_character_id` | Der Altwert wird übernommen (Altstandard an, neuer Standard aus; Hinweis, wenn an). |
| `KB_PUBLIC_ACCESS` | `knowledgebase.public_access` | Ja/Nein (Schreibweisen unten), nur wenn noch nicht gesetzt (außer mit `--overwrite-settings`). Auch bei abgeschaltetem Modul gespeichert. |
| `API_KEY`, `REGISTRATION_MODE`, `TABLET_LOGIN_ENABLED` | | Entität `auth_settings` (oben). |

- **Nicht gesetzt** sind leere Werte und die Beispielwerte `CHANGE_ME`, `Musterstadt`, `Musterweg 0815`, `1337`, `intraRP`, `ıgnıs` (ein Hinweis listet die Schlüssel). **Ja/Nein:** `true`, `1`, `yes`, `on`, `ja` bzw. `false`, `0`, `no`, `off`, `nein` und leer, ohne Beachtung der Groß-/Kleinschreibung; alles andere wird verworfen (Warnung). Das Altsystem las nur genau `true`, `1`, `yes` als "an"; liest der Import einen Wert anders (z. B. `TRUE`, `On`, `ja` ist jetzt an, war dort aus), nennt eine Warnung die Schlüssel (ohne Werte). Jeder Wert muss zusätzlich die Regeln der Einstellungsseite erfüllen (`SettingDefinitions`).
- **Nicht übernommen** (Hinweis mit Grund): `SYSTEM_URL` (die Adresse ist `APP_URL`; Warnung, wenn sie auf einen anderen Ort zeigt: verglichen werden Host (ohne Groß-/Kleinschreibung), Port außer dem Standardport und Pfad ohne abschließenden Schrägstrich; ein Altwert ohne Schema wie `intra.example.de` gilt als `https://`, das Schema selbst zählt nicht, weil Einladungs- und Discord-Links `APP_URL` nutzen), `BASE_PATH` (lief das Altsystem unter einem Unterpfad: `IGNIS_IMPORT_LEGACY_BASE_PATH` setzen), `CRON_ENDPOINT_TOKEN` (Scheduler statt Cron-Endpunkt), `TELEMETRY_*` (auch der Laufzeitwert `TELEMETRY_RATE_LIMIT_UNTIL`), `INSTALLATION_ID` (keine Telemetrie), `UI_NEW_NAVBAR_ENABLED`, `SETUP_MODULES_DONE`, `LANG`.
- **Datenschutz:** `ANNOUNCEMENTS_ENABLED`, `HUB_URL`, `FORUM_URL` werden nicht übernommen. Die Ankündigungs-Abrufe sind im Neubau ein Opt-in (Standard aus) unter Einstellungen > Datenschutz; die Adressen sind Umgebungsvariablen.
- **Discord:** Bot-Token und Bot-Einstellungen (`DISCORD_BOT_*`) werden **nicht** übernommen: das Token im Neusystem neu eintragen. Die Warnung nennt, welche Schlüssel im Altsystem gesetzt waren (`DISCORD_BOT_DM_TYPES` mit dem Saatwert `mail,system` nur, wenn der Bot an war oder ein Token hatte). Ebenso die Webhooks (`DISCORD_WEBHOOK_*`, die URL enthält ein Token): sie werden nicht übernommen und unter Einstellungen > System > Discord neu eingetragen. Beide Warnungen nennen nur die Namen der gesetzten Schlüssel; die Werte werden weder gelesen noch gespeichert noch ausgegeben.
- **Modul-Schlüssel:** `ENOTF_*`, `MAIL_*`, `FEDERATION_*` (und `FIRE_*` außer `FIRE_ASU_CONSUMPTION`/`FIRE_ASU_START_BAR`, die als `firetab.*` übernommen werden, und `FIRE_INCIDENT_REQUIRE_USER_AUTH`, das entfällt) werden gezählt und als Hinweis gelistet ("übernimmt der Import des jeweiligen Moduls"), aber hier nicht geschrieben; die Modul-Importer lesen `intra_config` selbst.
- **Unbekannte Schlüssel** (nicht in der Tabelle) werden übersprungen, eine Warnung nennt die ersten 20.
- **Logo:** Leer oder ein mitgeliefertes Logo (`/assets/img/ignis-wordmark.svg`, `defaultLogo.webp`, …) heißt "kein Logo". Übernommen wird nur ein Upload des Altsystems, also genau `/storage/branding/<32 Hex>.<png|jpg|jpeg|webp>`, und nur mit `--uploads`: die Datei aus `<PFAD>/storage/branding/` muss (auch über Symlinks aufgelöst) im Ordner liegen und die Prüfungen eines Uploads bestehen (PNG, JPEG, WebP, höchstens 2 MB, Pixelgrenze, kein SVG). Sie bekommt einen **neuen** Zufallsnamen auf der Disk `branding`. Eine externe Adresse, ein anderer Pfad, eine fehlende oder ungültige Datei und ein Lauf ohne `--uploads`: Warnung "Logo nicht kopiert", die Einstellung bleibt. Ein unverändertes Logo wird nicht noch einmal kopiert; ein vorhandenes anderes Logo bleibt, außer mit `--overwrite-settings` (dann wird die alte Datei gelöscht). Beim Trockenlauf wird geprüft, aber nichts kopiert.
- **Modul-Schalter** (`module_switch`): `intra_plugins.enabled` wird über die Tabelle `LegacyConfigMap::PLUGINS` (= `docs/dev/modules.md`, "Altsystem-Zuordnung") zu `modules.<name>.enabled`. Der Schalter wird auch für ein noch nicht installiertes Modul geschrieben; er wirkt, sobald das Modul kommt. Unbekannte Plugin-IDs werden gezählt (Warnung) und übersprungen, Kernmodule nie geschaltet (Hinweis).

## Wiederholen

Der Import ist wiederholbar und legt nichts doppelt an. Die Regeln:

- **Rollen und Konten: das Altsystem ist die Wahrheit.** Jeder weitere Lauf überschreibt Rang, Farbe, Rechte, Rolle, Namen, Aktiv-Status usw. wieder mit den Altwerten. Änderungen, die nach dem Import in der neuen Instanz an importierten Konten oder Rollen vorgenommen wurden, gehen dabei verloren. **Deshalb nur bis zur Umstellung wiederholen** ("nur vor der Umstellung wiederholen"), nicht danach.
- **Ausnahme Betreiber:** Ein vorhandenes Super-Admin-Konto wird nie herabgestuft, und ein deaktiviertes Altkonto desselben Benutzers deaktiviert es nicht (Warnung im Bericht). Das Konto, mit dem der Import angestoßen wird, sperrt sich so nicht aus.
- **Einstellungen: der Erste gewinnt.** Was in der neuen Instanz schon gespeichert ist, bleibt (die Einstellungsseite speichert keine Standardwerte, ein gespeicherter Wert ist also eine Entscheidung des Betreibers); der Bericht nennt die behaltenen Schlüssel. Mit `--overwrite-settings` ersetzen die Altwerte sie. Ausnahme `discord.redirect_path`: steht dort der Standardwert `/auth/discord/callback` (auch wenn der Betreiber ihn bewusst gesetzt hat), setzt jeder Lauf wieder `/auth/callback.php`.
- **Audit und Einladungscodes** werden über die alte ID bzw. den Code aktualisiert, nicht dupliziert.
- **Fahrzeuge:** POIs, Fahrzeuge, Mängel, Verlauf, Beladelisten, Vorlagen und Register-Einträge werden wie Konten mit den Altwerten überschrieben (auch `is_active`, Zeichen und Jobs, die in der neuen Instanz geändert wurden); in der neuen Instanz gelöschte kommen beim nächsten Lauf wieder.
- **Dokumente:** Vorlagen, Editor-Dokumente und Altdokumente werden ebenfalls mit den Altwerten überschrieben (auch Archiv-Kennzeichen und Inhalte, die in der neuen Instanz geändert wurden). Ausnahme: ein Editor-Dokument, das in der neuen Instanz schon ausgestellt ist, bleibt unverändert, wenn es im Altsystem noch ein Entwurf ist (Warnung). Ein in der neuen Instanz **gelöschtes** Dokument (Vorlage, Editor- oder Altdokument) ist nach dem nächsten Lauf wieder da, solange es im Altsystem existiert; endgültig löschen erst nach der Umstellung.
- **Personal:** Stammdaten, Akten und Akten-Log werden wie Konten mit den Altwerten überschrieben (das Altsystem ist die Wahrheit). Verknüpfungen Konto zu Akte werden nur hinzugefügt oder bestätigt, nie verschoben oder entfernt. Ein im Altsystem geändertes Profilbild wird neu kopiert; die vorherige Kopie bleibt als verwaiste Datei liegen.
- **Benachrichtigungen, Schnellzugriffe, ausgeblendete Ankündigungen:** werden mit den Altwerten überschrieben (auch der Gelesen-Status; in der neuen Instanz gelöschte kommen wieder). Benachrichtigungen finden sich über ihre UUIDv5 wieder, neue Benachrichtigungen der neuen Instanz bleiben unberührt.
- Konten, Rollen und Codes, die **nur** in der neuen Instanz existieren, werden nicht angefasst oder gelöscht (Rollen nennt der Bericht).

## Was nicht übernommen wird

- Discord-Bot-Token und Webhooks werden nicht übernommen (siehe oben).
- Die Cron-Historie wird nicht importiert (reine Laufdaten).

## Umstellung

Bei der Umstellung: Vorlauf mit einer Produktionskopie, Freeze, letzter Import mit `--overwrite-settings` und ohne `--import-api-key`, den API-Schlüssel rotieren und einen Rollback bereithalten. Nach dem Go-live den Import nicht mehr ausführen.

## Fehlersuche

| Meldung | Ursache und Abhilfe |
|---|---|
| `The app is not installed yet. Run ignis:install first.` | Neue Instanz erst installieren. |
| `The legacy connection is not configured (set LEGACY_DB_HOST ...)` | `LEGACY_DB_*` fehlt (bei Docker in der `.env` neben der `docker-compose.yml` setzen und `docker compose up -d` ausführen). |
| `The legacy database 'x' is the app's own database; refusing to import from it.` | Host, Port und Datenbankname der Alt- und der neuen Verbindung sind gleich. Geprüft werden nur diese drei Werte; derselbe Server unter anderem Namen (`localhost` und `127.0.0.1`) wird nicht erkannt. Darauf achten, dass `LEGACY_DB_DATABASE` wirklich die Altdatenbank ist. |
| `The legacy database is not reachable: ...` | Host, Port, Benutzer, Passwort oder Firewall prüfen. |
| `Legacy tables missing: ... Altsystem nicht auf dem letzten Stand?` | Im Altsystem die Migrationen ausführen (CLI `php cli/intra.php migrate`) und erneut starten. |
| `IGNIS_IMPORT_LEGACY_TIMEZONE 'x' is not a valid timezone` / `IGNIS_IMPORT_LEGACY_DB_TIMEZONE 'x' ...` | Zeitzonenname wie `Europe/Berlin` oder `UTC` eintragen (bei der Datenbankuhr auch leer lassen). |
| `--only`: unbekannte Entität | Gültige Namen: `role`, `user`, `registration_code`, `audit`, `auth_settings`, `rank`, `fire_qualification`, `ems_qualification`, `specialty`, `personnel_title`, `personnel`, `personnel_log`, `account_link`, `document_template`, `document`, `legacy_document`, `poi`, `vehicle`, `vehicle_defect`, `vehicle_defect_event`, `loadout`, `tactical_symbol_template`, `vehicle_registry`, `vehicle_audit_context`, `logbook`, `form`, `kb`, `calendar`, `manv`, `mail`, `notification`, `dashboard`, `announcement_dismissal`, `system_settings`, `module_switch`. |
